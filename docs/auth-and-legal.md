# Вход, согласия, юридические документы и скачивание приложения

## 1. Реквизиты оператора (обязательно заполнить)

В файле `frontend/lib/legal.ts` замените значения в квадратных скобках на настоящие: ФИО оператора,
город и e-mail для обращений. Они подставляются в Политику конфиденциальности и Условия использования.
При существенных изменениях текстов обновите `LEGAL_VERSION` и дату: версия записывается вместе с согласием.

Тексты документов (русский и казахский) лежат в `frontend/lib/legalTexts.ts`.
Это типовые документы, составленные по Закону РК № 94-V «О персональных данных и их защите». Это не юридическая
консультация: перед запуском для широкой аудитории покажите их юристу.

## 2. Письмо после регистрации ведёт на localhost

Адрес, на который ведёт ссылка из письма, задаётся в Supabase. В Supabase → Authentication → URL Configuration:

- **Site URL:** `https://eco-step-anj7.vercel.app`
- **Redirect URLs:** добавьте `https://eco-step-anj7.vercel.app/**` и `http://localhost:3000/**` (для разработки).

В коде при регистрации передаётся `emailRedirectTo` (адрес берётся из `NEXT_PUBLIC_SITE_URL`, а в браузере — из адреса сайта).
Для Android-приложения добавьте в `frontend/.env.local` строку `NEXT_PUBLIC_SITE_URL=https://eco-step-anj7.vercel.app`
до `npm run cap:sync`. Письма, отправленные до смены настроек, продолжат вести на старый адрес: такому пользователю
нужно зарегистрироваться заново или запросить письмо ещё раз.

## 3. Где хранится согласие

При регистрации согласие записывается в профиль пользователя (Supabase → Authentication → Users → поле `user_metadata`,
ключ `consent`: версия документов и время). Это подтверждение того, что согласие получено.

## 4. Скачивание приложения на сайте

Страница `/download` отдаёт файл `frontend/public/downloads/EcoStep.apk` и показывает размер, дату и контрольную сумму
(`apk-info.json`). Чтобы выложить новую версию:

```powershell
cd C:\EcoStep\frontend
npm run cap:sync        # собрать сайт и перенести в приложение
npm run cap:android     # открыть Android Studio → Build → Build APK(s)
npm run publish:apk     # скопировать готовый APK на сайт (после сборки в Android Studio)
cd ..
git add .
git commit -m "Новая версия приложения"
git push
```

`npm run cap:sync` автоматически исключает папку `downloads` из мобильной сборки, иначе APK оказался бы внутри самого
приложения и размер рос бы с каждой сборкой.
Если приложение пересобрано на другом компьютере, подпись у него может отличаться: тогда Android при обновлении
сообщит о конфликте, и пользователю нужно сначала удалить старую версию.
